## 1. Definitions, formulas and units

All quantities are **measured** from the per-request log of the load generator, at the client side of nginx.

| Quantity | Definition | Unit |
| --- | --- | --- |
| second | a 1 s bin of the observation window that holds at least one request | s |
| failed second | a second in which fewer than 99 % of the requests succeeded (SLO-1) | s |
| failure | a maximal run of failed seconds (runs one good second apart are merged) | count |
| T | observation window: the seconds of all repetitions of the scenario, added up | s |
| downtime D | number of failed seconds | s |
| MTTR | D / failures | s |
| MTTF | (T − D) / failures | s |
| MTBF | T / failures = MTTF + MTTR | s |
| availability A | MTTF / (MTTF + MTTR) = 1 − D / T | % |
| failure rate λ | failures / (T − D) | 1/h |
| request failure ratio | failed requests / requests | % |

With no failure in T, MTTF is censored (MTTF > T) and only an upper bound on the rate can be stated: λ ≤ 3 / T at 95 % confidence (rule of three). 

**The fault rate is not a property of the system.** Every scenario injects its fault on purpose, one per 70 to 90 s run and nine per 600 s soak run. MTTF, MTBF and λ below therefore describe the system *under this injected fault load*, which is many orders of magnitude harsher than real operation. What transfers to real operation is (a) MTTR, (b) the share of injected faults that become failures at all, and (c) the ratio between the modes.

## 4. Soak: which injected faults became failures

One soak run injects nine component faults, 60 s apart, each repaired 25 s after its injection (the repair delay is a parameter of the experiment: it stands for an operator who reacts in 25 s). A fault "became a failure" if at least one failed second lies between its injection and the next injection. Coverage = 1 − failures-causing faults / injected faults.

## 5. Series/parallel model (illustrative inputs)

This section is **not a measurement**. It shows what the redundancy structure is worth under an assumed, explicitly illustrative component failure behaviour, and uses measured restore times where the campaign provides them.

| Configuration | Structure | Availability (model) | Downtime per year (model) |
| --- | --- | --- | --- |
| baseline | series of 8: nginx, gateway, student ×2, payment ×2, transcript, database | 99.99632 % | 19.3 min |
| final | nginx · (gateway ∥ gateway) · (student ∥ student) · (payment ∥ payment) · (db ∥ db) · transcript | 99.99941 % | 3.1 min |

Formulas: A_component = MTTF / (MTTF + MTTR); series A = Π A_i; parallel A = 1 − Π (1 − A_i). The model assumes independent failures, which one Docker host does not give (a host failure is common-mode), and it treats a parallel pair as perfect, while the measurements in section 4 show that some faults still cost a few seconds. In the final structure the two single components (nginx, transcript) carry almost all of the modelled downtime.
